# 스펙 — 작업 감독 콘솔 UX

> 상태: Phase 1 구현 진행 · 범위: UX/정보구조/이벤트 표시
> 목적: 자동화 봇이 조용히 사라지는 것이 아니라, 사용자가 현재 목표·근거·위험·다음 행동을 계속 감독할 수 있게 한다.

## 해결하는 문제

현재 UX는 기능은 많지만 감독 경험이 약하다.

- 실행 중 창이 최소화되면 봇이 제대로 일하는지 보기 어렵다.
- 상태 바, 워크플로우, 실행 로그, 협업 HUD가 각각 흩어져 있다.
- 워크플로우 그래프가 화면 밖으로 나가거나 초기 템플릿이 허술하게 느껴진다.
- 사용자가 “지금 이 자동화가 왜 이 행동을 하는지” 즉시 알기 어렵다.
- MES/Office/배포처럼 위험도가 다른 업무가 모두 일반 채팅처럼 보인다.

감독 콘솔은 이 문제를 “더 많은 로그”가 아니라 **작업 관리성**으로 해결한다.

## 설계 원칙

1. **감독 가능한 자율성**: 자동 실행 중에도 현재 목표, 현재 단계, 근거, 위험 상태가 보여야 한다.
2. **방해하지 않는 존재감**: 화면을 가리기보다 작게 비켜 있지만, 완전히 사라지지는 않는다.
3. **위험 작업은 전면화**: 승인 필요, 파괴적 작업, MES 데이터 변경은 눈에 띄게 표시한다.
4. **워크플로우는 장식이 아니라 실행 지도**: 예쁜 그래프보다 현재 위치와 다음 행동이 중요하다.
5. **도메인별 전문성**: MES 검증, Office 작성, 배포 자동화는 서로 다른 템플릿과 상태 언어를 가진다.

## 현재 자산

이미 코드 안에 다음 재료가 있다.

| 자산 | 위치 | 활용 |
|------|------|------|
| 에이전트 상태 바 | `electron/renderer/chat.js` | 현재 상태/중단/끼어들기 |
| SSE 이벤트 | `agent/core/events.py`, `agent/server.py` | 실행 이벤트 스트림 |
| 워크플로우 패널 | `electron/renderer/workflow.js` | 단계, 그래프, 로그 |
| 실행 로그 탭 | `electron/renderer/workflow.js` | 도구 실행 결과 |
| 공용 HUD | `electron/main.js`, `electron/renderer/hud.*` | 협업 코치와 실행 감독을 함께 표시하는 작은 비탈취 창 |
| plan mode | `agent/server.py` | 계획 후 승인 실행 |
| safety gate | `agent/tools/_safety.py`, `agent/server.py` | 위험 작업 승인 |

1차 개편은 새 대형 프레임워크를 붙이지 않고, 이 자산을 “감독 콘솔”로 재배치한다.

감독 콘솔은 제품 내부 에이전트 하네스의 UI다. 런타임 역할 분리와 루프 구조는 `docs/specs/product-agent-harness.md`를 기준으로 한다.

## 정보 구조

우측 패널은 기존 `워크플로우 / 실행 로그`에서 다음 구조로 격상한다.

### 감독 탭

항상 처음 보이는 탭이다.

- 현재 목표
- 현재 작업 단계
- 실행 모드: 자동 / 계획 후 승인
- 현재 도구와 경과 시간
- 사용 중인 근거: 문서, 화면, 파일, 스레드
- 위험/승인 대기 항목
- 중단, 끼어들기, 승인/거부 버튼

### 워크플로우 탭

기존 그래프를 유지하되 의미를 명확히 한다.

- 그래프는 최초 렌더 시 반드시 화면 안에 fit-to-view 된다.
- 노드는 `대기 / 실행 중 / 승인 대기 / 완료 / 오류 / 건너뜀` 상태를 명확히 보여준다.
- 현재 실행 노드는 항상 자동으로 보이는 위치에 온다.
- 좁은 패널에서는 그래프 대신 세로 단계 목록을 기본으로 보여준다.

### 근거 탭

MES/Office 업무에 중요하다.

- 읽은 Office 문서
- 추출한 표/요구사항
- 참조한 화면 캡처
- 관련 Obsidian 노트
- 생성된 검증 증적

### 로그 탭

디버깅용 상세 로그다.

- 최근 도구 실행
- 실패 원인
- 타임아웃/재시도
- 원문 출력 접기/펼치기

## 작은 HUD 정책

현재 기본 동작인 “실행 중 자동 최소화”는 감독성을 떨어뜨린다.

새 기본값은 **작게 비켜 보기**다.

HUD는 다음만 보여준다.

- 현재 목표 축약
- 현재 단계 번호와 이름
- 현재 도구와 경과 시간
- 위험/승인 대기 여부
- 중단 버튼
- “자세히 보기” 버튼

창 모드 옵션:

| 모드 | 설명 | 기본 여부 |
|------|------|----------|
| 작게 비켜 보기 | 작은 HUD만 남기고 메인 창은 방해하지 않음 | 기본 |
| 반투명 | 메인 창을 투명하게 유지 | 선택 |
| 자동 최소화 | 기존 방식, 감독성 낮음 | 선택 |
| 끄기 | 개발/디버깅용 | 선택 |

## 이벤트 모델

1차 구현은 기존 SSE 이벤트를 프론트엔드에서 감독 이벤트로 변환한다.

| 기존 이벤트 | 감독 콘솔 표시 |
|------------|----------------|
| `request_id` | 현재 실행 ID |
| `agent_state` | 상태 배지 |
| `plan` | 계획/승인 단계 |
| `tool_start` | 현재 도구 시작 |
| `tool_wait` | 오래 걸리는 작업 경고 |
| `tool_done` | 도구 결과와 로그 |
| `workflow_update` | 단계 상태 갱신 |
| `confirm` | 승인 대기 카드 |
| `vision_capture` | 화면 근거 |
| `context_usage` | 컨텍스트 사용량 |
| `error` | 오류 상태 |
| `done` | 실행 종료 |

후속 단계에서는 `RunSnapshot` 또는 `RunLedger` 서버 모델을 추가해 새로고침 후에도 감독 상태를 복원한다.

## 도메인 템플릿 방향

### MES 명세서 검증

초기 워크플로우:

1. 명세서/변경요청 문서 수집
2. 요구사항과 테스트 항목 추출
3. MES 화면/배포 대상 확인
4. 위험 작업 분류 및 승인 요청
5. 검증 실행 또는 체크리스트 생성
6. 증적/리포트 저장

### Office 문서 작성

초기 워크플로우:

1. 입력 자료 확인
2. 문서 구조 설계
3. 초안 생성
4. 표/서식/검토의견 반영
5. 파일 저장 및 품질 점검

### 배포 자동화

초기 워크플로우:

1. 환경 확인
2. 배포 대상/버전 확인
3. 사전 검증
4. 승인 요청
5. 배포 실행
6. 결과 검증 및 로그 저장

## 오픈소스 패턴 매핑

| 출처 | 참고 패턴 | 적용 |
|------|----------|------|
| OpenHands | Agent Canvas | 감독 탭 + 워크플로우 + 근거를 하나의 작업 캔버스로 통합 |
| OpenHands | event stream / observability | SSE 이벤트를 실행 타임라인으로 시각화 |
| OpenHands | condenser | 긴 실행 이력을 요약해 현재 목표/근거만 상단에 유지 |
| OpenHands | delegation | 후속 제품 내부 planner/executor/verifier 역할 분리 |
| OpenClaw | live canvas | HUD와 우측 패널을 실시간 작업 관찰 화면으로 사용 |
| OpenClaw | local-first/session routing | 폐쇄망 PC에서 세션별 작업 상태 유지 |
| ECC/Claude Code | hooks/subagents | 개발 하네스에서 리뷰·테스트·완료 게이트 자동화 |

코드 반입은 하지 않고 기능 계약만 차용한다.

## 단계별 구현 계획

### Phase 1 — 프론트엔드 재배치

- [x] 우측 패널에 `감독` 탭 추가
- [x] 기존 SSE 이벤트를 프론트엔드 상태 reducer로 모아 표시
- [x] 현재 단계, 현재 도구, 경과 시간, 승인 대기, 근거 요약 표시
- [x] 기본 busy mode를 “작게 비켜 보기”로 변경
- [x] 그래프 최초 렌더 fit-to-view 보장
- [x] 실행 노드가 바뀌면 그래프 뷰를 현재 노드 쪽으로 보정
- [x] 감독 reducer를 `electron/renderer/supervisor-state.js`로 분리하고 Node fixture로 상태 전이를 검증
- [x] 기존 SSE 이벤트를 RunSnapshot 1차 `phase`/`role` 라벨로 표시

### Phase 2 — 실행 상태 영속화

- 서버에 `RunSnapshot` 또는 `RunLedger` 모델 추가
- 새로고침/스레드 전환 후에도 현재 실행 상태 복원
- 실행 증적과 감사추적 연결

### Phase 3 — 도메인별 감독 화면

- MES 검증, Office 작성, 배포 자동화 템플릿 고도화
- 근거 탭에 문서/표/화면/결과물을 도메인별로 표시
- 사용자용 완료 리포트 생성

## 수용 기준

- [x] 자동화 실행 중 현재 목표와 현재 단계가 항상 보인다.
- [x] 창이 최소화되어도 HUD에서 현재 단계/도구/위험 상태를 볼 수 있다.
- [x] 승인 대기 상태는 일반 로그가 아니라 별도 카드로 표시된다.
- [x] 워크플로우 그래프는 최초 표시 시 화면 밖으로 나가지 않는다.
- [x] 현재 실행 노드가 그래프/목록에서 명확히 강조된다.
- [x] 도구 실행이 오래 걸리면 경과 시간과 중단 버튼이 눈에 띈다.
- [ ] MES/Office/배포 업무별 초기 워크플로우가 일반 템플릿보다 구체적이다.
- [x] 구현 전 Playwright 또는 DOM 단위 테스트 기준이 정의된다.
