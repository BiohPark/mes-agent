# 백로그 O — 외부 기기에서 지시·모니터링 (원격 제어) 📱

> 상태: 🔲 미착수 · 사용자 선택: **다른 기기에서 지시 + 모니터링** · 폐쇄망 보안 설계가 관문

## 문제·가치

자리를 비워도 폰/다른 PC에서 작업을 던지고 진행 상황을 본다. 현재 서버는 **localhost 전용 +
Origin 게이트 + 토큰**(`agent/server.py` `_security_gate`)이라 원격 접근이 구조적으로 차단돼 있다.

## 접근 (폐쇄망 친화 2안 병행 검토)

### (A) Vault 매개 명령함 — 권장 1순위
- Obsidian Vault가 이미 동기화되는 점을 활용. 포트 개방 없이 **동기화만으로 원격 제어**.
- `agent/control/inbox.md`(또는 폴더)에 명령을 적으면, 서버가 **mtime 폴링**으로 집어 실행하고
  결과/상태를 `agent/control/status.md`에 기록. 다른 기기는 Obsidian으로 그 파일을 읽고/쓴다.
- **재사용**: `/threads/{...}/workflow/events`의 mtime 폴링 SSE 패턴(`server.py`), `obsidian_session._read/_write`.
- **장점**: 가장 안전(네트워크 노출 0), 폐쇄망 적합. **단점**: 실시간성은 동기화 주기에 의존.

### (B) LAN 바인딩 + 인증 강화
- `host=0.0.0.0` **옵트인** + Origin 허용목록에 LAN 대역 추가(`_origin_allowed`) + 토큰 **영속화·QR/PIN 페어링**.
- **장점**: 실시간. **단점**: 네트워크 노출 → 회사 정책·인증 강화 필수.

## Q와 공유
외부 명령 주입은 **작업 중 메시지 큐**(백로그 Q)와 동일 메커니즘. **Q 완료(2026-06-13)** 로 큐가 이미 존재한다:
`agent.server._pending_messages` + `POST /inject/{request_id}` + `generate()` 단계 경계 드레인.
O의 명령함 폴러는 inbox에서 읽은 명령을 **이 큐에 그대로 적재**(또는 활성 요청이 없으면 신규 `/chat` 시작)하면 된다.

## 핵심 파일 (예정)
- 수정: `agent/server.py`(명령함 폴러/인증/바인딩), `electron/main.js`(LAN 옵트인 토글·페어링 UI).
- 신규: `agent/control/*`(inbox/status 스키마).

## 확인 필요
1. **회사 네트워크 정책** — LAN 바인딩(0.0.0.0) 허용 여부.
2. Vault **동기화 수단**(Obsidian Sync / 네트워크드라이브 / 클라우드) 유무·지연.
3. 인증 모델(QR/PIN 페어링, 토큰 영속 저장 위치).
4. 권한 분리 — **모니터링만** vs **지시까지**(원격은 읽기, 위험작업은 로컬 승인?).
5. 감사 로그(누가 무엇을 원격 지시했는지).
