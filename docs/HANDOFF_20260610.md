# 인수인계 — mes-agent L1 루프 개선

## 목표
mes-agent(사내 폐쇄망 업무자동화 에이전트)의 실행 루프를 "강한 에이전트급
문제해결력"으로 끌어올린다. 루프를 새로 만들지 않고, 있는 것을 개선한다.

- 개발은 회사 밖에서, 결과를 폐쇄망 PC로 git pull. 런타임에 외부 네트워크 호출 금지.

- 테스트 실행: `.\test.ps1` 또는 `python -m pytest -q`. 현재 **374 passed, 1 skipped**.

## 현재 루프 (agent/server.py: generate())
OpenAI 스타일 스트리밍 tool-calling 루프. 이미 있는 것:
- 자동 디스커버리 툴 레지스트리(MANIFEST), `_MAX_STEPS=40`, `_CONTEXT_MAX_TOKENS=128_000`
- 확인 팝업 골격: `ask_user`의 `__confirm__` → CONFIRM SSE → `asyncio.Event` → `/confirm`.
  공통 헬퍼 `_resolve_confirm(cid)`로 일원화됨(타임아웃=거부).
- 정의 vs 실행상태 분리: WorkflowDefinition ↔ WorkflowRunState(set_node_status)
- 단계별 재시도: 워크플로 step `max_retry` 기반
- 안전 모듈 `agent/tools/_safety.py`
- **G3 중앙 안전 게이트(완료)**: `run_tool` 직전 `classify_risk`로 강제. (아래)
- **G1 컨텍스트 compaction(완료)**: 루프 진입부 자동 압축 + `COMPACTION` 고지. (아래)

## 지금 할 것 — G2(continuation nudge) 구현
새 세션에서 plan 모드로 계획부터. 계약서 **§6(G2)·§10(I3·I4)** 참고.

### 핵심 (계약 §6)
- 현재 `generate()`는 `finish_reason != "tool_calls"`면 **즉시 종료**(`break`).
- 개선: 모델이 도구 없이 텍스트로 멈췄을 때, **작업 미완으로 보이고** `nudge_count < MAX_NUDGES`(예 2)면
  `{"role":"user","content":"[시스템] 작업이 끝나지 않았다. 중단 사유가 없으면 계속 진행하라."}` 주입 후 루프 계속, `nudge_count++`.
- 완료 판단되거나 nudge 한도 소진 → 정상 종료(현행 `idle`+`DONE`).
- **불변조건**: `MAX_NUDGES` 상한으로 무한루프 방지(I3). nudge는 **텍스트-only stop에만**, tool_call 있으면 적용 안 함(원래 계속됨).

### 코드 앵커 (server.py, G1·G3 반영 후 — 마커로 재확인)
- 종료 분기: `if _stop_flags... or finish_reason != "tool_calls" or not tool_calls_raw:` → 이 `break` 직전이 nudge 삽입점.
- 실행상태 `nudge_count = 0`을 `compaction_count` 옆에 둔다.

### 테스트
- `tests/integration/test_server_chat.py`: 텍스트로만 멈추는 스크립트 LLM → nudge 주입돼 한 번 더 도는지, `MAX_NUDGES` 이후 멈추는지(I3), `DONE` 마감(I4). `_ScriptedStream` 재사용.
