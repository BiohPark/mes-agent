# 인수인계 — mes-agent L1 루프 개선

## 목표
mes-agent(사내 폐쇄망 업무자동화 에이전트)의 실행 루프를 "강한 에이전트급
문제해결력"으로 끌어올린다. 루프를 새로 만들지 않고, 있는 것을 개선한다.

## 환경/제약
- Python 3.11/conda, FastAPI(agent/server.py) + Electron UI. 사내 로컬 LLM(OpenAI 호환).
- 개발은 회사 밖에서, 결과를 폐쇄망 PC로 git pull. 런타임에 외부 네트워크 호출 금지.
- pytest는 환경에 포함돼야 함(과거 누락 이슈). 설치는 사람이 직접.
- 테스트 실행: `.\test.ps1` 또는 `python -m pytest -q`. 현재 **374 passed, 1 skipped**.

## 현재 루프 (agent/server.py: generate())
OpenAI 스타일 스트리밍 tool-calling 루프. 이미 있는 것:
- 자동 디스커버리 툴 레지스트리(MANIFEST), `_MAX_STEPS=40`, `_CONTEXT_MAX_TOKENS=128_000`
- 확인 팝업 골격: `ask_user`의 `__confirm__` → CONFIRM SSE → `asyncio.Event` → `/confirm`.
  공통 헬퍼 `_resolve_confirm(cid)`로 일원화됨(타임아웃=거부).
- 정의 vs 실행상태 분리: WorkflowDefinition ↔ WorkflowRunState(set_node_status)
- 단계별 재시도: 워크플로 step `max_retry` 기반
- 안전 모듈 `agent/tools/_safety.py`
- **G3 중앙 안전 게이트(완료)**: `run_tool` 직전 `classify_risk`로 강제. (아래)
- **G1 컨텍스트 compaction(완료)**: 루프 진입부 자동 압축 + `COMPACTION` 고지. (아래)
- **G2 continuation nudge(완료)**: 작업 도중 텍스트 조기종료 시 한도 내 '계속' 주입. (아래)
- **G4 plan 모드(완료)**: `agent_mode='plan'`이면 계획→승인→실행. (아래)

## 4가지 격차 진행상황 (docs/contracts/L1_loop_contract.md에 상세)

- **G3 (1순위) 안전 게이트 — ✅ 완료(2026-06-10)**
  - `_safety.classify_risk(tool_name,args,allowlist)→safe|mutate|destructive`.
  - `server.generate()`가 `run_tool` 직전에 호출해 강제(모델 force 우회 불가).
    safe→즉시, mutate/destructive→CONFIRM 팝업(예/항상/아니오)→`_resolve_confirm`.
    "항상"→`_session_allowlists`, 거부/타임아웃→미실행+사유 환류(짝 보존).
  - 균형형: 읽기·관찰·입력형=safe, 쓰기·삭제·셸변경·office편집·네트워크만 확인.
  - 테스트: `tests/unit/test_safety.py`(classify_risk), `tests/integration/test_server_chat.py::TestSafetyGate`.

- **G1 compaction — ✅ 완료(2026-06-10)**
  - `agent/core/compaction.py`: `compact_messages(messages,*,keep_recent,summarize_fn)`(요약 LLM 주입식, 순수) + `has_orphan_tool`. 짝 보존(I1): tail이 orphan tool로 시작하면 주인 assistant까지 경계 보정.
  - `server.generate()`: 루프 진입부에서 `_estimate_tokens > _CONTEXT_MAX_TOKENS*COMPACT_RATIO`(0.8)이고 `compaction_count<MAX_COMPACT`(3)면 압축 → `COMPACTION` SSE 고지. 요약은 모듈함수 `_summarize_history`(비스트리밍 1회, 테스트 monkeypatch 대상).
  - 상수: `COMPACT_RATIO=0.8`, `COMPACT_KEEP_RECENT=8`, `MAX_COMPACT=3`. 이벤트 `COMPACTION` 추가.
  - 테스트: `tests/unit/test_compaction.py`(7) + `tests/integration/test_server_chat.py::TestCompaction`(2).

- **G2 continuation nudge — ✅ 완료(2026-06-10)**
  - `server.generate()` 종료 분기: `tool_rounds>0`(작업 도중)이고 텍스트 조기종료면 `MAX_NUDGES=2` 내 `{"role":"user","content":_NUDGE_MESSAGE}` 주입 후 `continue`. 잡담(`tool_rounds==0`)·되묻기(`?` 종결)·사용자중단 제외.
  - 상수 `MAX_NUDGES=2`, `_NUDGE_MESSAGE`. 실행상태 `nudge_count`·`tool_rounds`.
  - 테스트: `tests/integration/test_server_chat.py::TestContinuationNudge`(4).

- **G4 plan 모드(PLAN1) — ✅ 완료(2026-06-10)**
  - `ChatRequest.agent_mode`("auto"|"plan") → `generate(agent_mode)`. `plan_phase`면 system에 `_PLAN_MODE_SUFFIX` + `PLAN` 이벤트.
  - 계획 단계 실행 차단: per-tc 루프에서 `workflow_*`/`ask_user` 외 도구는 미실행+안내 결과 환류(짝 보존).
  - 계획 완료(텍스트 stop) → `plan_approval` CONFIRM(승인 실행/수정 요청/취소), `_resolve_confirm` 재사용. 승인 시 `plan_phase=False`+승인 메시지 주입 후 실행 진입.
  - 프론트: 헤더 ⚡자동/📋계획 토글(localStorage), `/chat` body에 `agent_mode`.
  - 테스트: `tests/integration/test_server_chat.py::TestPlanMode`(3).
