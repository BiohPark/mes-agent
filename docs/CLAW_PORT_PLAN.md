# CLAW_PORT_PLAN.md

> REFACTOR_BRIEF.md의 짝꿍 문서. claw-code 계열의 하니스 패턴을 mes-agent에
> **클린룸(clean-room)으로 재구현**하기 위한 백로그 + Claude Code 운영 매뉴얼.

---

## 0. 절대 원칙 (클린룸)

법적 출처가 불명확한 코드(유출 파생)이므로 다음을 어기지 않는다.

1. 레퍼런스 저장소는 **읽기 전용 참고자료**다. 단 한 줄도 `src/`로 복사하지 않는다.
2. 레퍼런스는 mes-agent git 트리 **바깥**(또는 `.gitignore` 처리된 `ref/`)에 둔다.
   회사 코드베이스에 절대 함께 커밋되지 않게 한다.
3. 작업은 **2단계 분리**: ① 레퍼런스를 보고 *관찰 보고서*만 쓰는 세션,
   ② 그 관찰에서 뽑은 *계약서*만 보고 코드를 쓰는 세션.
   구현 세션에서는 레퍼런스 소스를 **다시 보지 않는다.** (진짜 클린룸의 핵심)
4. 레퍼런스 인용은 설명 목적의 5줄 이하 스니펫까지만. 통짜 복사 금지.

> 레퍼런스: `HarnessLab/claw-code-agent` (순수 Python, 무의존성 → 폐쇄망에서 읽기 좋음).
> 클론은 폐쇄망 **바깥**(Termux 브리지 또는 Mac Mini)에서.

## 1. 리스트(백로그) 짜는 법

리스트의 한 줄 = **하나의 서브시스템 = 하나의 계약(contract)**. 코드 줄 수가 아니라
계약 단위로 쪼갠다. 출처는 세 군데에서 길어온다:

- claw-code의 `PARITY_CHECKLIST.md` (그쪽이 정리해 둔 패턴 목록)
- 우리가 합의한 5개 서브시스템 (루프 / 툴 디스패치 / 권한 / 컨텍스트 / 프롬프트 조립)
- 기존 REFACTOR_BRIEF의 borrow target C1~C4

### 백로그 스키마

| 칼럼 | 의미 |
|---|---|
| ID | L1, T1 … 안정적 식별자 |
| 레퍼런스 출처 | claw-code 어느 파일/패턴인지 |
| mes-agent 매핑 | 우리 도메인 용어로 번역한 대상 |
| 우선순위 | P0(루프·툴·권한) → P1 → P2 |
| BRIEF 연결 | C1~C4 중 연결되는 것 |
| 상태 | TODO / 관찰완료 / 계약완료 / 구현완료 |

### 시드(seed) 항목 — 그대로 시작해도 됨

| ID | 레퍼런스 출처 | mes-agent 매핑 | 우선 | BRIEF |
|---|---|---|---|---|
| L1 | `agent_runtime.py` 의 LocalCodingAgent 루프 | 에이전트 실행 루프 | **P0** | C3 (정의/실행상태 분리) |
| T1 | `agent_tools.py` 툴 정의·디스패치 | activity 등록/디스패치 | **P0** | C1 (n8n 노드 모델) |
| P1 | `permissions.py` 4-tier | 사내용 권한 티어 | **P0** | (안전성) |
| X1 | (해당 없음) | 리트라이/에러 정책 | P1 | C2 (UiPath) |
| C1 | `agent_context.py` 컨텍스트 빌드 | 컨텍스트 조립 | P1 | Obsidian RAG |
| PR1 | `agent_prompting.py` 프롬프트 조립 | 시스템 프롬프트 조립 | P1 | — |
| S1 | `session_store.py` 세션 영속화 | 세션 영속화 | P2 | C3 |
| W1 | (해당 없음) | auto-wait 래퍼 | P2 | C4 (Playwright) |
| ❌ | `file/edit/glob/grep/bash` 툴 | **버림** (코딩 특화) | — | — |

> mes-agent는 **업무 자동화** 에이전트라 claw-code의 코딩 툴은 대부분 버리고,
> 그 자리에 "MES 화면 클릭 / 차트·이미지 인식 / Obsidian 기록" 같은 activity가 들어간다.

P0 세 개(L1·T1·P1)부터. 이게 "사용자가 원하는 것에 도달하는" 엔진의 심장이다.

## 2. Claude Code 운영 방식

**한 백로그 항목 = 한 작업 단위**, 각 항목을 3페이즈로 돌린다.
세션을 잘게 끊어야 컨텍스트가 안 터지고 클린룸이 지켜진다.

### 권장 디렉터리

```
mes-agent/
├─ REFACTOR_BRIEF.md
├─ CLAW_PORT_PLAN.md        # 이 파일
├─ docs/
│  ├─ observations/         # 페이즈 A 산출물 (레퍼런스 관찰)
│  └─ contracts/            # 페이즈 B 산출물 (우리말 계약서)
├─ src/                     # 페이즈 C 에서만 수정
└─ tests/
ref/                         # ← git 트리 밖 또는 .gitignore. 레퍼런스 클론.
```

### 페이즈 A — 관찰 (레퍼런스 읽기, 코드 수정 금지)

```text
역할: 너는 mes-agent 리팩토링을 돕는 시니어 엔지니어다.
먼저 REFACTOR_BRIEF.md 와 CLAW_PORT_PLAN.md 를 읽어라.

이번 작업: 백로그 L1 (에이전트 실행 루프).

클린룸 규칙:
- ref/ 아래 코드는 읽기 전용 참고자료다. 단 한 줄도 src/ 로 복사하지 마라.
- 이 단계에서 우리 코드(src/, tests/)는 절대 수정하지 마라.
- 출력은 관찰 보고서 파일 하나뿐이다.

작업:
1. ref/claw-code-agent/src/agent_runtime.py 의 루프를 읽어라.
2. docs/observations/L1_loop.md 를 한국어 산문으로 작성하라. 포함할 것:
   - 루프 1회전의 입력 / 출력
   - 종료조건 (stop_reason, max turns, 에러 이탈 경로)
   - tool_call 파싱 → 실행 → 결과 환류 경로
   - mes-agent(업무 자동화)에 해당 없는 코딩 특화 요소는 "버릴 것"으로 명시
3. 코드 인용은 5줄 이하 스니펫만, 설명용으로만.
끝나면 멈추고 보고만 하라. 다음 단계로 넘어가지 마라.
```

### 페이즈 B — 계약서 (우리 도메인 언어로 번역)

```text
역할: 동일. 입력: docs/observations/L1_loop.md (이것만 본다).
ref/ 소스는 이제 보지 마라.

작업: docs/contracts/L1_loop.md 를 작성하라.
- claw-code 용어가 아니라 우리 도메인 용어(activity, MES 화면, 차트 인식 등)로 번역.
- 명시할 것: 입력 / 출력 / 불변조건(invariant) / 종료조건 / 실패 모드 / 리트라이 정책.
- 리트라이 정책은 REFACTOR_BRIEF C2(UiPath 활동별 정책)를 따른다.
- 상태 표현은 C3(정의 vs 실행상태 분리) 원칙에 맞춰라.
코드는 아직 한 줄도 쓰지 마라.
```

### 페이즈 C — TDD 구현 (계약서만 보고 구현)

```text
역할: 동일. 입력: docs/contracts/L1_loop.md (이것만 본다).
ref/ 소스를 보지 마라. 계약서만 보고 우리 코드를 짠다.

작업(TDD 순서 엄수):
1. 계약서의 각 불변조건/종료조건에 대해 "실패하는" 테스트를 tests/ 에 먼저 작성.
2. 그 테스트를 통과시키는 최소 구현을 src/ 에 작성 (FastAPI 백엔드 관용구에 맞춰).
3. pytest 로 전부 통과 확인.

제약:
- 이번엔 L1 한 서브시스템만. 다른 파일은 건드리지 마라.
- 폐쇄망 PC에 pytest 누락 이슈가 있으니, 없으면 알려만 주고
  설치 명령(pip/conda)은 네가 실행하지 마라. 내가 직접 한다.
- 커밋 메시지 초안만 제안하고, git push 는 하지 마라.
```

### 세션 위생 (왜 이렇게 쪼개나)

- 한 항목 = 세 세션. 페이즈 넘어갈 때 새 세션/대화로 시작(컨텍스트 오염 방지).
- 구현 세션이 관찰 세션과 분리돼야 "계약서만 보고 짠" 진짜 클린룸이 된다.
- P0 3개(L1·T1·P1) 끝나면 한 번 통합 테스트 후 P1로.

## 3. 가드레일 체크리스트 (매 PR 전 확인)

- [ ] `ref/` 의 코드가 `src/`·`tests/` 어디에도 복사되지 않았다 (`git diff` 로 확인).
- [ ] `ref/` 가 커밋에 포함되지 않았다 (`.gitignore` 확인).
- [ ] 새 코드는 계약서 기반이며 레퍼런스 구조를 직역하지 않았다.
- [ ] 테스트가 먼저, 구현이 나중 (TDD 순서).
- [ ] 라이선스/컴플라이언스 이슈 시 사내 검토 완료.
